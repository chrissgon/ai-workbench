# Dana's notes (written by Dana)

## Small tools
- tinykv 0.5 is tagged in the repo: TTL support for keys, still zero dependencies. `wc -l` on src says 960 lines.
- Removed the last optional dependency, a colour crate for the CLI. The release binary went from 2.1 MB to 1.4 MB.

- tinykv's test suite: 212 tests, 1.8 s on my laptop, no mocks (every test opens a real file in a temp dir).
- Replaced the monitoring agent on the tinykv demo box with a 40-line shell script (cron, curl, disk check).
- Cut tinykv's README from 200 lines to 60 after watching 3 people skim it at the meetup.

## Database performance
- tinykv write benchmark on my laptop (bench/write.sh in the repo): fsync on every write, 900 writes/s; group commit every 5 ms, 26,000 writes/s.
- Side project load test (k6, 200 virtual users): shrinking the connection pool from 100 to 20 took p95 from 120 ms to 45 ms.
- A table with 30% dead tuples: autovacuum scale factor from 0.2 to 0.05, and the table size stayed flat for a week.
- Moved tinykv's index from a sorted array to a B-tree: a lookup among 1M keys went from 2.4 us to 0.9 us (bench/lookup.sh).
- Spent a morning reading EXPLAIN ANALYZE line by line instead of guessing: the slow step was a sort spilling 180 MB to disk.
- Lucas Ferreira at the Postgres meetup: a missing index on a foreign key made deletes take 40 s; with the index, 0.2 s.
- Reading Alex Petrov's Database Internals, the chapter on B-tree page splits; drew tinykv's splits by hand.

## AI for databases (built in public, nothing shipped)
- Query-hint experiment (an LLM suggests index hints): 3 of 10 test queries got faster, 2 got slower.
- Asked a model to rewrite slow queries: 2 of 5 rewrites returned different results, so every rewrite now runs against a results diff first.
- Schema in the prompt: without it the model invented a column in 4 of 10 answers; with it, 0 of 10.
- Cost log of the query-hint experiment: 1,240 model calls, 3.10 dollars in total.
- Asked a model to explain EXPLAIN output: it called a sequential scan an index scan in 1 of 8 plans.
- Tried a local 7B model for the hints: the same 3 queries got faster, but each suggestion took 40 s.
